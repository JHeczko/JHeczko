## 🚀 Featured Projects

#### 🫀 [CardioLatentNet](https://github.com/JHeczko/CardioLatentNet) - ECG latent space analysis with deep autoencoders
End-to-end pipeline for learning compact representations of ECG signals using deep autoencoders. Features latent space visualization, class separability analysis, and downstream multi-label classification.

**Key areas:** Time Series • Representation Learning • Deep Learning • Signal Processing

#### 🧠 [WrexGPT](https://github.com/JHeczko/WrexGPT) - GPT-2 from scratch in PyTorch
Implementation of a GPT-2 style transformer model trained on a Shakespeare dataset. Includes custom transformer blocks, an autoregressive training loop, tokenization pipeline, and text generation.

**Key areas:** Transformers • NLP • Deep Learning • Training Infrastructure

#### 📡 [ServicePulse](https://github.com/JHeczko/ServicePulse) - self-hosted uptime & observability platform
Full-stack monitoring platform inspired by Uptime Kuma, fully containerized with Docker Compose. FastAPI + SQLAlchemy backend, Dramatiq + Redis task queue with APScheduler driving per-service check intervals, JWT auth, structured logging - paired with a React 19 + TypeScript dashboard showing real-time uptime and response-time charts. GitHub Actions CI/CD ships images straight to Azure Container Registry.

**Key areas:** Fullstack web dev • Docker Compose • Task Queues • CI/CD to Azure • Observability

#### 🗄️ [TalkToDb](https://github.com/JHeczko/TalkToDB) - LangGraph-based Text-to-SQL pipeline
Built with a friend: a self-correcting Text-to-SQL system on LangGraph. Generated SQL is checked with sqlglot for syntax plus a semantic validation layer, feeding a self-correction loop when a query doesn't hold up, all sitting behind a FastAPI security layer.

**Key areas:** LangGraph • LLM Pipelines • SQL Validation • API Security

# 🎯 Engineering Focus
I like taking systems apart to see how the pieces fit - and building them back cleaner. That's the same instinct on both sides of what I do: on the infrastructure side, I'd rather understand why a deployment is flaky than just patch around it; on the ML side, I'd rather write the training loop and the architecture myself than import a library and hope for the best. I just really like to understand the whole and how it works.

I think in systems more than in tickets - how something behaves under load, what happens when it fails, what the whole pipeline looks like end to end, not just the piece directly in front of me. That's probably why DevOps and infrastructure work keeps finding me on team projects, and why I keep coming back to building models from scratch instead of just fine-tuning someone else's.
